## 背景与目标

用户提供的 10 首音源足以交付一个完整可玩的网页版。沿用真实素材，完成可重建、可预览、可继续扩充的本地版本，不擅自下载新的歌曲、不公开部署有版权的素材。

## 交付物清单

1. README 完整运行说明：Node/ffmpeg 前置、安装、资源生成/校验、开发与生产本地预览、资源缺失排查。
2. 四模式/三难度规则表与参考差异；明确歌词模式扩展、混合为副歌顺序连播，默认 72 秒为待人工校准切片起点，不声称每首都取到了真正副歌。
3. 曲库扩充说明：沿用每首一个文件夹 mp3/lrc/jpg、元数据与 chorusStartSec 配置、重新生成与 verify、改源音频/封面后 --force；不改动现有 music。
4. 更新 tools README 的歌词产物/指纹/阈值/验证说明，plans 总览补齐实际提交链和完成状态。
5. 最终自测：npm test、npm run build、assets --verify，生产预览访问真实资产与一次完整游戏；源码/文档/计划流程可追溯，无生成音频或 dist 提交。
6. 实现纪要、独立实现评阅、一次提交，保留本地可访问的预览入口。

## 涉及文件

`README.md`、`tools/prepare-audio/README.md`、`plans/README.md`、本计划四件套。若最终验收发现实际功能缺陷，单列在纪要并回到对应 plan 返修，不用文档掩盖。

## 实现步骤

1. 确认 git 基线与前置提交，核对实际 npm 命令、CLI 行为和应用规则。
2. 修改文档及总览，对已有资料修订保持溯源。
3. 运行最终检查，生产本地预览与真实页面操作验证。
4. 独立 review，PASS 后提交并确认 main 工作树整洁。

## 风险与回滚

文档命令对系统 ffmpeg PATH 和本地音源有依赖，明确检查方法；本版本不附带公开素材授权。不处理未提供的更多歌曲，按指南后续扩充。回滚本次文档提交即可，不影响游戏资产。
