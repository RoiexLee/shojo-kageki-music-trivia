# Plan 006：舞台透明主视觉与动效升级

## 背景与目标

当前游戏已经具备完整猜歌流程，但首页主视觉使用带白底的横幅，舞台主题不够突出；页面状态切换也缺少入场、聚光灯和星屑等连续动效。成绩分享文案中的时间单位还缺少中文空格，导致复制文本和下载图片的排版不统一。

本计划在不改变猜歌规则和 `music/` 素材的前提下：

1. 统一页面、复制文案和下载成绩图的时间格式为“用时 45 秒”或“用时 1 分 23 秒”。
2. 使用已核验的官方透明角色 PNG，在舞台背景上构成可响应式缩放的主视觉。
3. 为首页、答题页和结算页补充有节制的舞台灯光、帷幕、星屑、波形和内容入场动效，并支持 `prefers-reduced-motion`。
4. 通过桌面与 375px 移动端浏览器走查，确认透明素材、主要交互和响应式布局可用。

## 交付物清单

- [ ] `apps/web/public/theme/characters/` 下至少 3 个来源明确且真实透明的官方角色 PNG。
- [ ] 首页主视觉改为透明角色叠加舞台背景，移除对白底横幅的主依赖。
- [ ] 首页、答题页、结算页拥有一致的舞台氛围动效；减少动态偏好下不闪烁、不漂移。
- [ ] 分享文案、结算页和下载成绩图的时间文案使用中文空格。
- [ ] 相关 formatter 单测、全量测试、生产构建、资源校验通过。
- [ ] `implementation.md` 记录实际改动、偏差、五项以上视觉对比和浏览器证据。
- [ ] `implementation-review.md` 由只读 reviewer 评阅并给出 `VERDICT: PASS` 或完成返修复核。

## 实现步骤

1. 检查当前 git 基线和未提交变更，清理与本计划无关的 `package-lock.json` 噪声。
2. 通过已核验的官方资源 URL 下载透明角色 PNG，记录来源与版权边界，不把素材上传到公开远端。
3. 在纯函数层修复时间 formatter，并更新分享相关断言，确保秒、分钟边界稳定。
4. 抽出或新增舞台主视觉组件，保持文字、按钮和状态由 React 控制；用 CSS 分层承载背景、角色、光束、帷幕和星屑。
5. 将主视觉接入首页，并为答题、结算状态添加轻量入场与反馈动效；保留现有可访问名称、焦点和交互。
6. 添加移动端断点和 `prefers-reduced-motion` 覆盖，避免角色遮挡文本、横向溢出或内容不可读。
7. 执行 `npm test`、`npm run build`、`npm run assets -- --verify`，启动开发服务器并用 IAB 检查桌面与 375px 首页、答题、结算流程。
8. 编写实现纪要，交由 reviewer 只读评阅；若为 `FIX`，按清单返修并追加复核结论。
9. 评阅通过后由 orchestrator 提交 `plan-006(web): 舞台透明主视觉与动效升级`。

## 验收标准

- [ ] 导出/复制文案显示 `用时 45 秒`、`用时 1 分 23 秒`，不出现 `45秒` 或 `1分23秒`。
- [ ] 首页主视觉在浏览器中可见透明角色边缘，角色与舞台背景自然融合，未使用白底横幅作为主视觉。
- [ ] 首页首次进入、模式选择、答题状态、结算状态均有可辨识且不过度的舞台动效。
- [ ] `prefers-reduced-motion: reduce` 下无持续漂移/闪烁，所有文本和操作仍可用。
- [ ] 桌面视口和 375px 视口无内容裁切、横向滚动或按钮不可点击。
- [ ] `npm test`、`npm run build`、`npm run assets -- --verify` 全部通过。
- [ ] 浏览器控制台无新增运行时错误，至少完成一次“首页→开始→答题→结算”的交互路径。

## 风险与回滚

- 官方角色图体积较大，可能增加本地首次加载时间；通过 `loading`、尺寸属性和 CSS 裁切控制，必要时只保留 3 张角色图。
- 外部官方 URL 未来可能变化；来源和文件名集中记录，删除角色层即可回退到现有 `cast.png` 降级视觉。
- 动效可能影响低性能设备或无障碍用户；使用 CSS 媒体查询统一关闭，并保持内容不依赖动画完成。
- 若浏览器验收发现遮挡或资源加载失败，可回滚舞台组件与 CSS，保留 formatter 修复和既有玩法。
