## 背景与目标

基础游戏已具备四种玩法。本计划将首页、答题、结算统一为少女☆歌剧的舞台节目单风格，并补齐前两计划遗留的真实浏览器验收。使用前端构建、图像生成、React 最佳实践、前端测试技能；用户已授权自主决定设计，无需等待用户选稿。

## 交付物清单

1. 深酒红背景、象牙白文字、香槟金描边、玫红主操作的统一 CSS tokens；首页左标题右官网主视觉，下方四种模式及难度、开始按钮。标题“听见旋律，再赴舞台。”；信息来自真实曲库。图像生成概念仅作布局参考，角色与 logo 使用查实的官方素材（有意偏差：不使用 AI 重绘角色）。若生成服务失败，记录原因后使用同样明确的文字设计规格。
2. 官网主视觉与白色 logo 下载到 `apps/web/public/theme/`；不依赖运行时外链，保留来源与版权。原始图片不做 AI 改绘；可由 ffmpeg 生成适合网页的压缩副本。失败时使用既有本地封面及文字标题，不画假角色或标注虚假授权。
3. 答题页沿用同一视觉体系；长曲名完整换行、不在揭晓前显示封面或泄露答案；真实播放状态与队列编号、可重放/暂停、返回首页、正确/错误文字反馈。移动端触控目标至少 44px、键盘焦点清晰，减少动态效果偏好生效。
4. 结算页展示模式/难度、成绩、耗时、种子、最佳成绩、各题答案与封面。最小成绩分享：复制纯文字与本地下载 Canvas PNG（不上传、不含二维码占位），失败给出可理解提示。
5. `docs/research/revue-starlight-songs.md` 补官方素材直链与查证日期，纠正 Star Parade 日文括注及《恋は太陽》演唱者表述；记录 MyGO 参考差异（本项目混合为顺序连播，歌词为新增玩法）。`NOTICE.md` 补素材来源。
6. 中文实现纪要、独立实现评阅、通过后一次 git commit。

## 设计落地规格（评阅后细化，不增加功能范围）

概念已由内置 Image Gen 生成并查看：`exec-869bbd07-16ad-4a9d-825f-8c78bb37f8d8.png`（仓库外设计证据）。采用其首页信息顺序、左大标题右主视觉、下方模式与难度操作条；官方图片内容与概念中的 AI 角色/帷幕不同，明确以官方素材为准，不宣称像素级一致。

- tokens：背景 #170f18，表面 #231820，正文 #f6ecdc，弱文字 #c6b9ae，金色 #d6b579，主按钮 #bb3451，描边金色低透明度；反馈另有绿/红语义色，集中 CSS 变量。
- 字体：标题宋体/Mincho 衬线，正文系统中文/日文字体；桌面首页标题 64px，手机 42px；正文 16px，说明 13px；按钮最小高度 44px。
- 首页：最大宽度 1120px，顶部 logo 与非官方标记；hero 左文右官网九人图；四模式一行，手机两列；操作条含三难度、随选择更新的规则和开始按钮；版权 footer。
- 官方素材：使用 `animation/tv/visual_pc.png` 九人横幅与 `logo_white@2x.png`；背景可用 `animation/tv/bg_caststaff_pc.png` 加统一深酒红遮层。素材来源见研究纪要，下载到 theme/；不使用网络字体。
- 答题：最大宽度 820px、品牌 header、返回、题号/分数、10 格进度、歌词或播放器、2 列选项（手机1列）、反馈与下一题；播放可暂停/重放，状态真实。
- 结算：最大宽度 880px，突出分数，模式难度/用时/最佳与 seed，复制与下载、再玩一次；逐题封面与完整歌名列表。
- 图标仅必要的播放、暂停与方向箭头，使用简单规范 SVG；无装饰图标库。所有交互文字均代码渲染，图片不嵌入虚假 UI。
- 概念文案纠正：混合模式说明采用“多首副歌依次连播，选出全部歌曲”，避免概念图“多种方式混合”歧义；功能性加载/错误/规则说明是必要补充。无新营销模块。
